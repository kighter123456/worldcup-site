# 世界杯数据门户网站 —— 数据库表详细设计(字段级)

> 本文档是《功能清单与数据库表设计.md》的配套文档,内容为数据库表的**字段级设计**。
> 功能清单、表间关系(ER)见主文档;本文档只讲"表怎么建、字段怎么定"。
> 技术栈:PHP + MySQL 8.0.16+(Yii2 advanced,MVC)。主题:世界杯。数据范围:近 40 年(1986~2026)多届。
>
> **第 2 版(2026-10-18)**:比赛表由 `match` 改名为 `game`;新增点球大战比分、进球归属球队、助攻、胜场积分等字段。实际以 `data/install.sql` 为准。

---

## 一、通用约定

- **命名规范**:表名小写 + 下划线、用单数;主键统一 `id`;外键统一 `xxx_id`;创建时间统一 `create_time`(datetime,`NOT NULL DEFAULT CURRENT_TIMESTAMP`)。
- **字段命名**:字段名一律使用英文,避免中文/拼音字段名带来的编码兼容问题;中文只出现在字段的「值」和 `COMMENT` 注释里。
- **字符集与引擎**:统一 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`,否则中文数据会乱码。
- **索引约定**:所有外键字段建普通索引;关联表建**唯一索引**防重复(见各表);状态/时间类查询用复合索引。
- **约束**:MySQL 8.0.16+ 支持 `CHECK`,本设计用它兜住主客队不同、比分非负、状态取值、单例表等规则。5.7 可执行但 CHECK 不生效,此时需在模型 `rules()` 里补校验。
- **时间字段**:`create_time` 由数据库默认值填充,同时建议每个模型加 `TimestampBehavior`,不要在后台表单里让用户填。

## 二、核心表(14 张)

### 1. `tournament` 届次
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| year | int | 年份(1986~2026),**UNIQUE** |
| name | varchar(100) | 官方名称(如"2022年卡塔尔世界杯") |
| host_country | varchar(100) | 东道主,多国用文本(如"韩国/日本") |
| team_count | int | 参赛队数(24 / 32 / 48) |
| format | varchar(100) | 赛制说明(如"32队/8组/小组前2晋级"),供后台 B2 展示 |
| win_points | tinyint | 胜一场积分,**默认 3**;1986、1990 两届为 **2** |
| start_date | date | 开幕日期 |
| end_date | date | 闭幕日期 |
| create_time | datetime | 创建时间 |

> 届次是「多届建模」的锚点,所有随届次变化的数据都通过 `tournament_id` 关联到本表。
> `win_points` 是积分榜正确性的关键:世界杯 1994 年起才改 3 分制,硬编码 3 分会把 1986/1990 两届算错。

### 2. `team` 球队 / 国家队
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| name | varchar(50) | 队名 / 国名,**UNIQUE** |
| code | varchar(10) | FIFA 三字码(BRA / GER / ARG),**UNIQUE** |
| continent | varchar(20) | 所属大洲 |
| flag | varchar(255) | 国旗图片路径 |
| logo | varchar(255) | 队徽图片路径 |
| intro | text | 球队简介 |
| create_time | datetime | 创建时间 |

> 球队是「维度表」,身份稳定、跨届不变;小组 / 教练 / 排名等每届都变的事实放在 `tournament_team`。
> 历史身份按 FIFA 口径拆行:西德(FRG)、苏联(URS)、捷克斯洛伐克(TCH)、南斯拉夫(YUG)不与现代德国/俄罗斯/捷克/塞尔维亚合并,用 `code` 区分。

### 3. `player` 球员
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| name | varchar(50) | 姓名 |
| birth_date | date | 出生日期 |
| nationality | varchar(50) | 国籍(仅展示;代表哪队以 squad 为准) |
| position | varchar(20) | 主要位置 |
| photo | varchar(255) | 照片路径 |
| intro | text | 简介 |
| create_time | datetime | 创建时间 |

> 进球 / 助攻数不落库,由 `goal` 表统计。球员入选哪届哪队、穿几号,由 `squad` 表承载。

### 4. `tournament_team` 参赛队伍
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| tournament_id | int FK | → tournament.id |
| team_id | int FK | → team.id |
| group_name | varchar(10) | 该届所在小组(视届次 A~F / A~H / A~L) |
| coach | varchar(50) | 该届主教练 |
| fifa_rank | int | 参赛时 FIFA 排名 |
| final_rank | int | 最终名次(可选) |
| create_time | datetime | 创建时间 |

> **UNIQUE (tournament_id, team_id)**。"某队在某届是哪个组"的唯一权威来源;`game` 不再存小组,由本表推导。
> 小组数量随赛制变化:1986~1994 为 A~F,1998~2022 为 A~H,2026 为 A~L。

### 5. `squad` 参赛名单
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| tournament_id | int FK | → tournament.id |
| team_id | int FK | → team.id |
| player_id | int FK | → player.id |
| shirt_number | int | 该届球衣号(1~99) |
| position | varchar(20) | 该届位置(可选,默认取 player.position) |
| create_time | datetime | 创建时间 |

> **UNIQUE (tournament_id, player_id)**:一名球员在一届世界杯只能代表一支球队。
> **UNIQUE (tournament_id, team_id, shirt_number)**:同队同届球衣号不重复(`shirt_number` 为 NULL 时不受限,表示号码未知)。
> 这两个唯一键缺一不可——少第一个会让射手榜 COUNT 翻倍,少第二个会出现同队两人同号。

### 6. `game` 比赛
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| tournament_id | int FK | → tournament.id |
| home_team_id | int FK | 主队 → team.id |
| away_team_id | int FK | 客队 → team.id |
| home_score | int | 主队比分(**120 分钟含加时,不含点球大战**) |
| away_score | int | 客队比分(**120 分钟含加时,不含点球大战**) |
| home_penalty_score | tinyint unsigned | 点球大战主队比分(无点球大战为 NULL) |
| away_penalty_score | tinyint unsigned | 点球大战客队比分(无点球大战为 NULL) |
| match_time | datetime | 比赛时间 |
| stage | varchar(20) | 阶段(小组赛 / 1/16决赛 / 1/8决赛 / 1/4决赛 / 半决赛 / 三四名决赛 / 决赛) |
| venue | varchar(50) | 比赛场地(文本,如"卢塞尔球场") |
| status | tinyint | 状态(0未赛 1进行中 2已结束) |
| create_time | datetime | 创建时间 |

> **表名说明**:原设计叫 `match`,但 `match` 是 PHP 8 的保留关键字,按表名生成的模型类 `class Match` 无法编译(Gii 会直接失败),故改名为 `game`。模型类为 `Game`。
> **点球大战**:常规比分与点球比分分列存放,页面展示为 `1-1(5-3)`。点球大战的进球不要算进 `home_score`/`away_score`,也不要污染射手榜。
> **不存小组**:按小组筛选比赛时 `JOIN tournament_team`(以 home_team_id 匹配)取 group_name,保持单一数据源。
> **CHECK**:主队 ≠ 客队;比分非负;`status` ∈ (0,1,2);`status=2` 时两个比分必须非空。

### 7. `goal` 进球记录
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| game_id | int FK | → game.id |
| team_id | int FK | **进球归属球队** → team.id(乌龙球填受益方) |
| player_id | int FK | 进球球员 → player.id(乌龙球填防守方球员) |
| assist_player_id | int FK | 助攻球员 → player.id(可空) |
| minute | int | 进球分钟(1~130) |
| is_penalty | tinyint | 是否点球(0/1) |
| is_own_goal | tinyint | 是否乌龙(0/1) |
| is_shootout | tinyint | 是否点球大战进球(0/1,统计射手榜与球队进球时排除) |
| create_time | datetime | 创建时间 |

> **`team_id` 是统计正确性的核心**,不要再用 `player_id + squad` 反推球队:
> - 普通进球:进球球员在该届所属球队;
> - 乌龙球:记给对方球队(受益方),不是乌龙球员所在队。
>
> **统计口径**:
> - 射手榜:`WHERE is_shootout = 0 AND is_own_goal = 0`,按 `player_id` 分组;
> - 各队进球:`WHERE is_shootout = 0`,按 `team_id` 分组(乌龙球已天然归到受益方);
> - 一次进球最多记一名助攻者,`assist_player_id` 为空表示无助攻。

### 8. `comment` 留言(评论式核心表)
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| user_id | int FK | → user.id(留言需登录,不允许为空) |
| content | text | 内容 |
| target_type | varchar(20) | 挂载实体:team / player / game / news / tournament |
| target_id | int | 挂载实体 id |
| parent_id | int FK | 父留言 id,**NULL 表示顶层**(自引用,ON DELETE CASCADE) |
| status | tinyint | 状态(0正常 1已删除) |
| create_time | datetime | 创建时间 |

> 关键设计:一张表通过 `target_type` + `target_id` 挂载到任意实体,无需每个实体各建一张留言表。
> 索引:复合索引 `(target_type, target_id)` + `parent_id` + `user_id`。
> `parent_id` 用 NULL 而不是 0,这样才能建自引用外键:删除父留言时,整棵回复树会级联删除。
> **前台留言需要登录**:`user_id` 非空,前台使用 Yii2 advanced 自带的注册/登录。
> **删除实体时要清理留言**:多态挂载无法建外键,删除 team/player/game/news/tournament 时,需在 `beforeDelete()` 里执行 `Comment::deleteAll(['target_type'=>..., 'target_id'=>...])`。

### 9. `user` 用户(普通用户 + 管理员共用)
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| username | varchar(50) | 登录名,**UNIQUE** |
| password | varchar(255) | 密码(用 PHP `password_hash()` 加密,勿用 md5) |
| nickname | varchar(50) | 昵称(留言显示用) |
| avatar | varchar(255) | 头像 |
| role | tinyint | 角色(0普通用户 1管理员 2超管) |
| create_time | datetime | 创建时间 |

> 管理员与普通用户共用本表,后台登录仅校验 `role >= 1`;不单设 `admin` 表。
> **注意**:不要直接复用 Yii2 advanced 模板自带的 `common\models\User`——它期待 `password_hash`/`auth_key`/`created_at` 等字段,与本表不一致,会登录失败。请自建实现 `IdentityInterface` 的模型。
> 密码字段不要放进 Gii 生成的 CRUD 表单和搜索条件,否则会被当普通文本改坏或直接显示。

| create_time | datetime | 创建时间 |

### 11. `team_info` 团队介绍(团队展示页用)
| 字段 | 类型 | 说明 |
|---|---|---|
| id | tinyint PK | **固定为 1**(单例),非自增 |
| name | varchar(50) | 团队名 |
| logo | varchar(255) | 团队 Logo |
| slogan | varchar(100) | 团队口号 |
| intro | text | 团队介绍 |
| create_time | datetime | 创建时间 |

> 单例表(全站仅一条记录):作业要求「后台:团队信息编辑」,故团队介绍入库,管理员才能在后台改。
> 数据库层用 `CHECK (id = 1)` 保证永远只有一条;后台只生成 update,不生成 create/delete。
> **注意**:`id` 没有 `AUTO_INCREMENT`,插入时不要显式写 `id`(默认就是 1)。

### 12. `work` 作业文件(下载页用)
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| title | varchar(100) | 文件名/标题 |
| type | varchar(20) | 类型(团队/个人),默认"团队" |
| file_path | varchar(255) | 文件路径(**NOT NULL**,指向 /data/team 或 /data/personal) |
| description | varchar(255) | 说明 |
| create_time | datetime | 上传时间 |

> 存的是文件**元数据**(路径/标题/说明),文件本体放磁盘不落库;作业要求后台可改下载文件,故需要本表。
> `file_path` 非空:没有文件的作业记录没有意义。`type` 由后台下拉框限定为"团队/个人",不要自由输入。

### 13. `news` 资讯 / 公告发布
| 字段 | 类型 | 说明 |
|---|---|---|

| title | varchar(100) | 标题 |
| content | text | 正文 |
| author | varchar(50) | 作者 |
| cover | varchar(255) | 封面图 |
| status | tinyint | 状态(0草稿 1发布) |
| publish_time | datetime | 发布时间 |

### 14. `comment_like` 留言点赞
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK AI | 主键 |
| comment_id | int FK | → comment.id |
| user_id | int FK | → user.id |
| create_time | datetime | 点赞时间 |

> **UNIQUE (comment_id, user_id)**:防止同一用户重复点赞。
> 点赞需要登录;已删除(`status = 1`)的留言不允许再点赞,查询和写入都应先校验 `comment.status = 0`。

## 三、统计口径速查(实现动态图时照这个写)

| 统计项 | 表 | 关键条件 |
|---|---|---|
| 积分榜 | `game` + `tournament_team` | 只取 `stage = '小组赛'`;胜场积分取 `tournament.win_points`;按小组分组算胜/平/负、进/失球、净胜球 |
| 射手榜 | `goal` | `is_shootout = 0 AND is_own_goal = 0`,按 `player_id` 分组 |
| 各队进球分布 | `goal` | `is_shootout = 0`,按 `team_id` 分组(乌龙球已归受益方) |
| 助攻榜(可选) | `goal` | `assist_player_id IS NOT NULL AND is_shootout = 0`,按 `assist_player_id` 分组 |

## 四、删除策略

| 删除对象 | 结果 | 说明 |
|---|---|---|
| 届次 `tournament` | **级联删除**该届的参赛队、名单、比赛、进球 | 后台必须二次确认,误删不可恢复 |
| 比赛 `game` | 级联删除该场进球 | 正常操作 |
| 留言 `comment` | 级联删除其回复与点赞 | `parent_id` 自引用 + `comment_like` 外键 |
| 球队 `team` / 球员 `player` | **禁止删除**(RESTRICT) | 只要有任何比赛/名单/进球引用就删不掉;后台捕获 `IntegrityException`,提示"该球队还有 3 场比赛,请先删除关联数据" |
