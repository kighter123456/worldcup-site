## 一、注释头模板(作业硬性要求)

作业原文要求:**「每个 php 文件,加注释头」**。老师给的样子是:

```php
/**
 * Team: DBIS,NKU
 * Coding by niepeng 016096, 20170703
 * This is the main layout of frontend web.
 *
 * @var $this \yii\web\View
 * @var $content string
 */
```

拆开就是四要素:**队伍名 / 编写人 + 学号 / 日期 / 文件说明**。我们完全沿用这个格式,只在四要素里把「文件说明」细化成「模块 + 说明」两行,方便最后做实现文档和 PPT 时按模块统计每个人的工作量。

### 1.1 类文件(控制器 / 模型 / 组件)

```php
<?php
/**
 * Team: 国足世界杯夺冠队
 * Coding by 张三 20231234, 20261016
 * 模块:球队与球员 —— 球队列表控制器
 *
 * 处理前台球队列表与球队详情页的数据准备。
 */

namespace frontend\controllers;

use common\models\Team;
use yii\web\Controller;

class TeamController extends Controller
{
    // ...
}
```

### 1.2 视图文件(带 `@var`)

视图里有框架注入的变量,注释头要保留 `@var` 行——这既是老师示例里的写法,也能让 IDE 认出变量类型、少报错。

```php
<?php
/**
 * Team: 国足世界杯夺冠队
 * Coding by 张三 20231234, 20261016
 * 模块:球队与球员 —— 球队列表视图
 *
 * @var yii\web\View $this
 * @var common\models\Team[] $teams
 */
```

> `@var` 行的写法:`@var 类型 $变量名`。控制器里 `$this->render('index', ['teams' => $teams])` 传了几个变量,这里就写几行。

### 1.3 静态资源(可选)

css / js 建议照同样格式加 `/* */` 头,虽然不是硬性要求,但实现文档截图时可读性更好:

```css
/* Team: 国足世界杯夺冠队
   Coding by 张三 20231234, 20261016
   模块:球队与球员 —— 球队列表页样式 */
```

### 1.4 使用约定

- `Team:` / `Coding by` 两行**保持老师示例的关键字格式不变**,后面的内容和「模块/说明」用中文写。
- **日期格式 `YYYYMMDD`**(如 `20261016`),填**该文件最后一次修改**的日期——你改了内容就把日期一起更新。这条一定要记牢,否则到后期没人会回头改。
- 注释块紧跟 `<?php` 之后、`namespace` 之前。
- **团队作业里所有我们自己写的 php 文件都要有**:frontend、backend、common 下的控制器、模型、组件、配置文件。
- `vendor/` 目录下的第三方代码**不要动**。
- 模板里没有固定姓名,谁写谁填自己的名字和学号。
- 模型文件可另外补 `@property` / `@method` 注释(Yii2 的 Active Record 常用),那是 IDE 提示用的,和注释头不冲突。

## 二、数据库命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 表名 | 全小写 + 下划线,**用单数** | `team`、`tournament_team`、`comment_like` |
| 字段名 | 全小写 + 下划线 | `home_team_id`、`group_name` |
| 主键 | 统一叫 `id` | `id` |
| 外键 | `<关联表名单数>_id` | `tournament_id`、`home_team_id`、`player_id` |
| 时间字段 | `create_time` / `update_time`(datetime) | `create_time` |
| 布尔字段 | `is_` 前缀 | `is_penalty`、`is_own_goal` |
| 状态字段 | 统一叫 `status`(tinyint),取值写进字段注释 | `status` = 0/1/2 |
| 唯一索引 | `uk_字段名` | `uk_comment_user` |
| 普通索引 | `idx_字段名` | `idx_tournament` |
| 外键约束 | `fk_表名_字段名` | `fk_match_tournament` |
| 关联表命名 | 两个表名直接拼接 | `tournament_team`、`comment_like` |

**通用约定**

- 表名一律**单数**(`team` 不写 `teams`):表名代表「实体」而非「行数集合」,这样 Yii2 里模型类名 `Team` 能和表名一一对应。
- 字段名**用英文**,不用拼音、不用中文,避免编码与框架兼容问题。中文只出现在字段的「值」里。
- 每个字段都要写 `COMMENT` 中文注释——将来直接抽出来就是设计文档里的**数据库字典**,不用另做一份。
- 表名控制在 30 字符以内;不用 MySQL 保留字。
- 字符集与引擎统一 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`。

> ⚠️ **比赛表已从 `match` 改名为 `game`(2026-10-18)**
>
> `match` 不只是 MySQL 保留字,还是 **PHP 8 的保留关键字**——按它生成的模型类
> `class Match extends ActiveRecord` 会直接报 `Parse error: syntax error, unexpected token "match"`,
> 模块③一开工就会被卡死,而且报错信息和业务代码毫无关系,极难排查。
> 改成 `game` 之后 SQL 和 PHP 两侧都不再需要特殊处理。
>
> 看过第 1 版文档的成员请注意同步:凡是写 `match` 的地方一律改成 `game`,
> 进球表的外键列也从 `match_id` 改成了 `game_id`。

## 三、PHP 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 类名 | 大驼峰,单数 | `Team`、`TeamController`、`TournamentTeam` |
| 类文件 | 与类名同名 | `TeamController.php` |
| 命名空间 | 与目录结构一致,全小写 | `frontend\controllers`、`common\models` |
| 方法 | 小驼峰 | `getFullName()` |
| 控制器动作 | `action` + 大驼峰 | `actionIndex()`、`actionView()` |
| 变量 / 公开属性 | 小驼峰 | `$teamList`、`$homeScore` |
| 私有 / 受保护属性 | **下划线前缀**(Yii2 官方规范) | `$_models`、`$_totalCount` |
| 常量 | 全大写 + 下划线 | `STATUS_DELETED` |
| 数组键 | 与数据库字段同名(snake_case) | `$data['home_team_id']` |

**其他要求**

- **一个文件只放一个类**,类名 = 文件名,命名空间 = 目录路径(PSR-12 要求,Yii2 的自动加载也依赖这一点)。
- 所有方法、属性都要**显式写** `public` / `protected` / `private`,不使用 `var`。
- **缩进统一 4 个空格**(与 Gii 自动生成的代码一致;不要用 Tab,也不要混合)。用编辑器的话在设置里把 Tab 设成「插入 4 个空格」。
- 左花括号与声明同行(`class Team extends Model {` 下一行开始内容)。

## 四、视图 / 路由 / 静态资源命名

- **视图目录 = 对应模型名的小写**:`common\models\Team` → `frontend/views/team/`;`TournamentTeam` → `views/tournament-team/`。
- **视图文件名沿用 Gii 生成的默认名,不要改**:
  - `index.php` 列表页
  - `view.php` 详情页
  - `create.php` / `update.php` 新增 / 修改
  - `_form.php` 表单局部视图
- **局部视图(片段)以 `_` 开头**:`_form.php`、`_comment.php`、`_chart.php`。这些是给 `renderPartial` 或 `$this->render` 内嵌用的,不会单独成为一个页面。
- **路由 = 控制器名 / 动作名**,全小写、连字符分隔:`TournamentTeamController::actionIndex` → 路由 `tournament-team/index`。
- **静态资源**(`frontend/web/` 下):文件名全小写 + 连字符,**不用中文名、不用空格**。
  - 图片 `frontend/web/images/team/bra-flag.png`
  - 样式 `frontend/web/css/site.css`
  - 脚本 `frontend/web/js/comment.js`
- **上传文件目录**:`frontend/web/uploads/{team,player,news,avatar}/`。
- **图片路径入库只存相对路径字符串**(如 `uploads/team/bra-flag.png`),图片文件本体放磁盘,**不入库**。
- **作业文件放 `data/team/` 和 `data/personal/`**,这是作业硬性要求;下载页从 `work` 表读元数据。

## 五、文件编码与格式

- 文件编码:**UTF-8 无 BOM**。
- 换行符:**LF**(不要 CRLF)。
- php 文件**结尾不写 `?>`**(Yii2 / Gii 风格,避免末尾空白被输出到页面)。
- 页面与数据库统一 **utf8mb4**,否则中文数据会乱码。

## 七、外部依据

本规范不是自己拍的,对照了三个来源,只有少数几处按我们的实际情况做了取舍:

1. **PSR-12**(PHP 官方事实标准):类名大驼峰、方法小驼峰、常量全大写、一文件一类、命名空间映射目录——我们的 PHP 部分基本就是它。
   - 出处:<https://www.php-fig.org/psr/psr-12/>
2. **Yii2 官方编码规范**(`yiisoft/yii2-coding-standards`):整体基于 PSR-12,额外规定私有/受保护变量用下划线前缀(§三已采纳)。
   - 出处:<https://github.com/yiisoft/yii2-coding-standards>
3. **MySQL 通用命名约定**:小写 + 下划线、单数表名、避开保留字、索引前缀 `idx_` / `uk_`——这套在国内团队规范里是主流做法。
   - 出处:<https://github.com/anjuke/coding-style/blob/master/mysql/mysql-guideline.md>

**刻意不一致的地方(免得起争议)**

- Yii2 框架自身源码用 **Tab** 缩进,而 PSR-12 与 Gii 生成代码用 **4 空格**。我们选 **4 空格**,因为我们大多数文件是 Gii 生成的,混合两种缩进只会更乱。
- 唯一索引前缀用 `uk_` 而非 `uniq_`——两者都常见,选 `uk_` 是为了和国内通行的 `idx_` / `uk_` 组合保持一致。
